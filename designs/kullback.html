Your traces in. A model out.

Kullback is the agent behind leibler. It reads the logs your agent already writes, rebuilds the world the agent worked in, grades any model on what it changed, and trains on the runs that pass.

You read it and decide.

What a week of traces turns into.

Data

The records your runs touched, with the values they saw.

Tools

One function per tool, behaving the way the real one did in the logs.

Rules

Your policy, turned into checks that run before every write.

User

A simulated user who knows only what the real one knew.

Verifier

One per task. It looks at the final data and says pass or fail.

Every value points back to the line in your trace it came from. Nothing is invented.

Built so you can trust the numbers.

Grade what changed, not what was said.

Required writes present, forbidden writes absent, policy never broken, the user's questions answered. Where judgment is unavoidable, two judges each cite a span and a disagreement goes to a person.

A stand-in is reported, never counted.

Tool calls go to code first, then to an exact recording, then to a model stand-in. A run served by a stand-in anywhere is excluded from every number.

Any model behind one id.

Built-in adapters and the models.dev registry, so a provider nobody wrote code for is one flag away. Keys come from the environment, never from a command line.

You read everything it makes.

Every eval case and every training example Kullback writes stays readable. Reject one and it rewrites. The runner is frozen only when a person confirms it, and every verdict carries the hash of both the environment and the runner.

Three ways to run it.

As a pipeline.

Six commands, from ingesting traces to the report, in CI or on a laptop.

As a screen.

A terminal screen that watches stages, gates and spend as the build runs.

As a loop.

Resume from the cache and keep improving, or hand the session to the model.

Tests run fully offline and builds reproduce byte for byte from fixtures.

Read it, run it, or let it run for you.
